# 钓未知技法箱(前 / 中 / 后)

> 属 [[unknowns-to-gates]];总图与症状路由见 SKILL.md §2。
> 每个技法标注:治哪格 / 要点 / 例句。例句可直接抄给用户,也可由 agent 主动向用户发起。
> 不必每次全用——按 §2 路由表选,用哪个取决于此刻哪个象限在冒风险。

**媒介原则(全技法箱通用)**:钓未知的产物必须用**用户反应成本最低**的媒介呈现——
HTML 对比页 / 定帧图 / 多帧 GIF / 可点原型 > 散文列表。因为 UK 的暴露机制是"瞬间识别",
散文触发不了它;同一内容换成能"看"的形态,显影效率差一个量级。(原文:几乎所有场景
HTML artifact 都是最好的载体;本项目对应物:定帧、帧条、kimi 可读视频。)

## 实现前

### 0. 目标回声 — 治 KK 传递失真(最便宜的技法,开工第一动作)

动工前,agent 用自己的话复述:**我理解的目标是什么 / 成功长什么样 / 验收者是谁的眼睛 / 我打算怎么走**,
给用户 10 秒确认。指代词("类似的动画""那种效果")必须展开成具体所指——传递失真几乎全藏在指代词里。
(文创 AR 案例 之鉴:"做冰箱贴里的动画"被理解成"把磁贴画面动起来",一字未错,所指全偏,直到强烈反馈后才纠正。)

### 1. Blindspot pass(盲点扫描)— 治 UU,尤其 b 型静默封顶

新领域开工第一步。agent 主动列出"用户可能不知道自己不知道的":领域核心概念、历史坑、
**"好能有多好"的参照系**、成熟管线里有而我们流程里没有的工序。

要点:
- 用户给足起点上下文(我是谁 / 我懂什么 / 这块哪里是新的)——没有起点,盲点扫描退化成泛泛科普。
- 用字面词 "blindspot pass" / "unknown unknowns" 触发。
- 输出按**猜错单价**排序,不按字母序。

例句:
- "我要做汕头小公园的 AR,但我对骑楼建筑史和 AR 触发约束都不熟。先做一个 blindspot pass:列出我大概率没意识到的未知,按猜错单价排序,先别动工。"
- "我不懂调色但这条片要调色。先教我建立这个领域的地图——让我知道'好'长什么样,再谈方案。"

### 2. 原型 / brainstorm — 两种用法,治两种未知

**(a) 多方向审美原型 — 治 UK(看到才知道的标准)**
用户的审美 / 标准无法预先言传时,**别问,直接给 3-4 个截然不同方向的低成本原型让用户反应**。

**(b) 可行性探针(spike)— 治"能不能做到"的 KU**
对疆域能力不确定("转录精度够剪 um 吗""XR-Frame 撑得住这个粒子量吗")时,不调研不猜,
直接做**一次性最小原型**去问疆域。前提是失败便宜;产物用后即弃,不许滑进生产代码。

要点:
- 先给"能看的",不给"能跑的"(不接后端、不维护状态、不进管线)。
- 方向间距离要大——贴着中庸出 4 个 = 白做。
- 用户的每个反应都是一次 UK 显影,**当场记下来变成 KK 并入覆盖表**,不许只留在对话里。
- 几乎每个编码/创作 session 都该以探索或 brainstorm 开场——它同时防 scope 定得过窄或过宽。
- **挑不动信号**:用户面对 N 个变体挑不出、或都不满意但说不出为什么——缺的不是选项,
  是判断标准 = **UU-b 确诊**。停止再出变体,切 T1 补课模式:先教用户这个领域"好"长什么样,
  再回来挑。(Fable 发布视频调色案例:先学调色,再谈方案。)

例句:
- "先别写实现。给我 4 个视觉方向截然不同的定帧(HTML/图),我挑了方向你再动工。"
- "把这个磁贴的 AR 创意出 3 个构图方向的分镜首帧,我反应完再进管线。"

### 3. Interview — 治 UK / KU

原型反应完仍有未知 → agent 采访用户。

纪律:
- 一次一问;优先问"答案会改变架构 / 美术方向"的;每问附一句为什么这个问题重要。
- 问出的答案直接写进决策覆盖表(closure.md §1)——否则象限倒退。

例句:
- "开工前 interview 我:一次一个问题,只问模糊处,优先问我的回答会改变架构的。"

### 4. References(参照物)— 治不可言传的 UK

说不清想要什么时,最好的表达是参照物。优先级:**源码 > 对标视频(kimi 拉片)> 图 > 文字形容**。
源码/实物承载了全部隐性决策,文字形容只承载你意识到的那部分。

⚠️ 红线:**相关性 ≠ 复刻**。参照给的是语汇 / 氛围 / 质感标准,不是让你 1:1 搬(复刻 17 层铺子之鉴)。

例句:
- "vendor/rate-limiter 这个库实现了我要的退避语义。读它,在我们的 TS client 里重实现同样语义。"
- "这条对标视频的 pop-out 节奏是我要的。拉片提取它的运镜与节奏语汇,别照抄内容。"

### 5. 实现计划排序 — 治 KU

出实现计划时,把"最可能被用户改"的排最前:美术方向 / 构图 / 数据模型 / 类型接口 / 用户可见流程;
机械重构沉底并声明"这部分不用看"。让用户的 review 火力集中在高方差决策上。

例句:
- "写实现计划,把我最可能改的(构图/配色/交互流程)放最前,机械部分放最后标'不用看'。"

## 实现中

### 6. Deviations log(强制)

`implementation-notes.md`,每条:遇到什么 / 选了什么 / 为什么保守 / 属哪个象限。
它是下一轮计划的原料,也是执行中冒出的未知的固定落点(没有落点 = 落进对话里 = 蒸发)。

### 7. Tripwire 判档 + 岔路口亮牌(细则见 SKILL.md §5)

撞到未知先判档再动作。特别警惕:**"看起来只有一种合理做法"是 C 档未知最常见的伪装**——
显然性是你自己地图上的属性,不是疆域的属性。

**岔路口亮牌**:路径选择失败的主形态不是"选错",是**"没被识别为选择"**。凡是存在 ≥2 条可行路径的
节点(资产来源 / 工序次序 / 验收方式 / 空间语法…),哪怕你有明确偏好,也要先把它**标记成岔路口**:
写一行"此处有选择:A(我推荐,因为…)/ B / C",再按档位处置(C 档亮给用户,B 档记 log 走推荐)。
(文创 AR 案例 之鉴:6 个重大岔路口只有 1 个被显式决策,其余 5 个被默认/惯性代做,全靠用户碰撞才翻转。)

### 8. 升级判据

发现推翻的是**计划的前提**而非细节 → 停,回 SKILL.md §4 重新开工,不在错误前提上堆工作量。
判别句:"如果开工前就知道这个,计划还会长这样吗?"——答否即升级。

## 实现后

### 9. 未知复盘(强制,5 分钟级)

流程见 SKILL.md §6。核心三问:最贵的未知是哪个 / 归哪个象限 / 哪个技法本可提前钓到。

### 10. Quiz(可选)

长会话后,agent 出带上下文的改动报告 + 测验,用户满分才 merge。
治的是"用户对成品的理解债"——diff 只给浅层理解,大量行为取决于既有代码路径。

### 11. Pitch / explainer

把原型 + spec + deviations log 打包成一份可转发文档(开头放 demo GIF)。
评审者与你有同样的起点未知——替他们把未知提前答掉,理解和批准都会加速。
