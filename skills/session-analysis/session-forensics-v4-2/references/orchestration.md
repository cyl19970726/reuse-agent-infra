# 谁来建图，要不要请人核

## 模型：观察者必须是强模型

建图、判主线、写答案，用当前能用的最强模型（Claude：Opus 级；Codex：最高档）。测试里 Haiku 级两版都失败：把说法当事实、主线判反、字段留空。
- 派观察者 subagent 时显式指定模型，不要继承默认。
- 核对者可以用 Sonnet 级。Haiku 级只跑脚本这类机械活。
- 自己是小模型：先说明这一点，建议换强模型或交给强模型（`brief.py observer`），不硬做判断。

## 默认：主 agent 自己建一张图

认知留在一个上下文里：建图的人就是回答问题、之后继续更新地图的人。会话长只影响挑哪几段读（先读纠正、插话和最近几段）。约 20–50 次调用。

## 派一个观察者：主 agent 不是强模型，或要把整件事交出去

`python3 scripts/brief.py observer --question "<原话>" --sessions A=<路径> [--origin O=<路径>] --repo <仓库> --out <地图目录>`
写 `brief-observer.md`，第一行是「这次唯一要回答的问题：<原话>」，第二行写明要求的模型：派错了的 agent 读到就先报出自己的模型并停下。
路径都转成绝对路径并当场查存在（subagent 的工作目录和主 agent 不同）。提示词就是「读 <目录>/brief-observer.md 并照做」，模型显式指定为最强。
它交回的第一段就是答案；主 agent 读 `map.md` 接住这份认知。

## 请一位核对者：结论要拿去用

什么时候：要定责、改规范、防再犯；或主 agent 对中心没把握。
`python3 scripts/brief.py challenger --question "<原话>" --sessions A=<路径> --map <目录>/map.json --ledger <目录>/ledger.json --out <目录>/check`
- 核对者新来，没有主 agent 的上下文：核 5 条关键结论，回答「中心对不对」「缺了什么」（没问的、没读的——尤其现成的 skill 和文档、没核的）。
- 要定责而主因有两种说得通的说法：加两次 `--rival "说法"`，同一位核对者顺带裁决哪种站得住、最早本该在哪停。按证据，不按票数。
  裁决主因是定责的判断，这时核对者也用最强模型（派工说明第二行会写）。
- 主 agent 对最终结论负责：说过头的要么改，要么在节点上写清为什么保留；改了什么写进 `method.checks`。全程约 60–100 次调用。

## 派工的纪律

- 派工说明第一行是这次唯一要回答的问题。上下文里出现与它无关的消息时，不去回答，先答题；需要的话在回复末尾说一句收到了。
- 核对者不读旧报告、旧地图的草稿；原始 JSONL 不进任何人的上下文，只用 `drill.py`。派工说明是文件，事后可以审计。
- 页面上不写「核对者」「视角」这类词：在「怎么查的」里写「另请一位核对了 5 条结论，改了其中 2 条：……」。
