# 版式和写作规则（report.html / map.md）

`scripts/render.py map.json` 生成 `report.html`（给人读）和 `map.md`（给 agent 读）。版式固定，agent 的工作是把 map.json 写好。

## 版式（render.py 已实现）

**首屏：这次问题的答案。**
1. 标题 + 一行说明（观察对象、几个会话、更新时间，本地时区）；「这份报告回答」：`question` 原样放。
2. **答案**：`lead` 一到三句，然后按 type 排必备项（进度、接手先带主线状态条）；
   提炼是「想法 ← 起因 ← 状态」表，改流程是现状、目标两张流程图 + 改动表 + 下一轮看的数。外部 skill 的 `ext`（`place: top`）跟在后面。
3. **现成资源**：和这次工作直接相关却没用上的，每条一句「项目里有 X，这次没有用上」。
4. **缺什么**：`answer.missing` + 这次没读的。
5. **想先问你**：属于这次答案类型的反问、问推断目标的反问（任何类型都上），每个带「为什么问」和「没人答时按什么继续」。
6. **这段时间发生了什么**（更新模式）。

**然后是地图，三节，默认折起：**
- 01 任务地图：主线 + 四格、目标（确认状态、AI 的理解和差在哪）、计划走到哪、卡在哪、下一步、协作两栏、现场核对、发起查看时说的。
- 02 你说过什么：按目标分组；超过 30 条时每个目标下只列还开着的、改了方向的，其余折起。
- 03 过程和怎么查的：时间线（点的高度 = 改动落在哪层，黄底 = 打转）、步骤表、关键产物、现成资源表、会话和做法。

明暗主题都能读，手机宽度下表格变竖排，页面不横向滚动，不引用外部库。

## 写作规则

**首屏最重要。** 读者 3 分钟读完首屏和答案之后的正文。
- `lead` 直接回答问题；回复用户的第一段就是它。主线不是「在主线上」时第一句就说。
- 首屏不出现编号（R/G/K/S/P/X）和「会话:行」，放进 `refs`（页面上是可悬停的「依据」）。只检查本图定义过的编号，「Kimi K2.5」这类名字不算。
- 主线只看三件事：最近的步骤还在不在计划里、有没有在同一个问题上反复尝试而没变好、当前那一步是不是停在等用户拍板。
- 做到哪：已完成什么、实测过什么；只有 agent 自己说的，写「agent 说……」。不写「基本完成」。
- 最大问题：一个，追到机制（「没先看一份导出样本」），不停在症状（「解析有误」）。第一件事：第一件实际要做的事。

**讲人话。** 页面上不出现内部词（骨架、脚本名、档位、视角、反方）；说「核对过原文」「只是说法」「另请一位核对了 5 条结论」。
中文，短句，一格一行一张卡只说一件事。**对事不对人**：协作两栏都写，用户侧写「消息可以怎么更好」。

**不把说法当事实。** agent 说「通过了」「用户同意了」，要找到对应的行（工具结果、文件、用户原话）；只有自述撑着的标 `说法`，页面显示虚线徽标。
根因默认是推断，有一行直接显示机制才标 `root_basis: 物证`。局限里写了「没读 X」而补读只要几分钟，就先读再交付。

**报告可能被转发。** 账本已把密码、token、密钥换成「[已遮蔽]」；其他敏感内容写进地图前自己判断。

**长会话要收。** 批准类已折进前一条；目标可以按区间认领请求；过程控制在 12 步以内；问题一般 ≤6 个。
