# 心智模型（完整版）

## 1. 两条流

```
叙事流  reasoning / assistant message / plan / 摘要 / compaction summary   = 辩护，永远自洽
物证流  exec / apply_patch / 测试输出 / 耗时 / 失败 / commit / 用户纠正     = 事实，不自洽但不说谎
```

**所有失败都是两条流之间的裂缝。裂缝是唯一的一等对象。**

裂缝的具体形态：
- 虚假通过 = 宣称"修好了"，物证流里没有覆盖那个表面的验证动作
- 隧道视野 = 叙事流还在说"正在推进目标 X"，物证流已连续几十个动作在同一文件来回改
- 重复踩坑 = 教训进了叙事流（写成笔记），没进物证流（没变成 gate/test）
- 目标漂移 = 最初的用户物证与最后 20% 的动作指向两件不同的事

## 2. 两类裂缝

```
A 类 时序裂缝   宣称 vs 自己的动作        局部可查    原理上可自察（虽难）
B 类 代际裂缝   引用 vs 被引用物的现状     全局才可查   原理上不可自察
```

B 类通用形式：**引用了一个已不再成立的东西，而系统没有失效传播机制。**
即 cache invalidation 缺失——agent 的整个工作状态是一个没有失效机制的缓存。

## 3. 为什么执行 agent 原理上看不见 B 类

三条互相独立的机制，任何一条单独成立都足够：

**判据封闭性** — 计划是封闭的成功判据集合，"计划本身错了"不在集合内。
计划这台机器只能生成"下一步"，生成不了"停"。每一次失败都会被计划解释成"还差一步"。

**类型不足** — 计划的类型是 `[Action]`；风险住在 `Action → PastConclusions → Invalid`。
而计划在 t=0 制定，那一刻结论集为空 → **原理上无法引用一个尚不存在的东西**。
所以这不是"考虑得不周"，把计划写详细一百倍也长不出这条边——详细度提升的是 action 的分辨率，
改变不了类型。

**压缩致盲** — 实测某会话 18 次 compaction，每段「34k 起步 → 冲到 240k → 压回 34k」，
每次丢弃约 195k token 物证换回约 900 token 叙事增量，**压缩比 ~200:1**，累计丢弃约 350 万 token。
摘要保留"做了什么、结论是什么"，丢弃"做了多少次、在几个副本里做的"——**而后者就是全部病理信号**。
**摘要算法的优化目标与 B 类裂缝的证据精确反相关。第 1 次压缩后即失效，不是第 18 次。**

这条只说明**跨段物证与关系**致盲，不等于“原始用户目标被删除”。实测 Codex 的一个 60 次
compaction 会话（`CASE-D`）在最后一次 `replacement_history` 中仍保留 **229 条 role=user
消息**。真正丢失或退化的是：

- 目标之间的 `introduced_by / supersedes / 当前有效性` 关系没有结构化保存，原话被摊平成长列表；
- 子任务经过「父目标 → 分派 prompt → 子 agent 报告 → 父会话 compaction」多级有损投影；
- 支撑目标取舍的 assistant reasoning、tool output 与跨段计数被压成叙事，最近局部目标更容易占据工作集。

所以 compaction **不会自动制造目标漂移**。它降低的是“从当前动作反查全局目标与变更依据”的可达性；
是否真的漂移仍须由 P3 判断：变更能追溯到 user message 是合法演化，追溯不到才是 agent 自漂。

→ 外部 agent 的不可替代性由此获得精确定义：**它的工作集是全局的**，能做那次执行 agent 做不到的
O(n) 重验。这是复杂度层面的分工，不是"第二双眼睛"这种软说法。

## 4. 与计划正交的对象：失效表

```
当 <某类动作> 发生  →  <某类已有结论> 失效
```

不是序列，是执行期持续生效的规则集。它是唯一能装下 B 类风险的容器。
**签名表是检测器，失效表是知识库**——同一事物的两面。

### 已知失效边（跨项目通用部分）

```
patch(tools/** | scripts/** | harness/**)  → 依赖该仪器的全部证据失效
deploy                                      → 全部部署新鲜度断言失效
修改场景/用例定义                            → 引用该定义的全部通过记录失效
修改术语/分层定义文档                        → 引用该术语的全部结论失效
在新工作树里改仪器                           → 该树之外的全部证据不可比
用户变更目标                                 → 旧目标下的全部结论/证据/已完成工作需重新估值
compaction 发生                             → 全部"跨段模式类"结论失效（压缩前的重复计数不可信）
```

最后两条最容易被忽略：没人把"用户改主意"和"上下文压缩"当成技术事件。

### 冻结 commit 为什么有效

它是在**没有失效表的情况下，用最粗暴的方式**（禁止一切仪器变更）保证证据有效性。
有了失效表就能精细化：允许改仪器，但改完自动把受影响的证据标 stale。

## 5. 三种用法 = 探针 + 装配

```
探针（可独立跑、可组合）          装配
  P1  裂缝 / 失效边检测            audit report   = P1 (+P3) (+P2)
  P2  可复用序列提取（沉淀）        harvest report = P2
  P3  目标演化追踪                 handoff packet = S + P1 + P2 + P3   ← 超集
  S   状态重建（完整版仅 handoff）
```

三者共享同一个物证层，只是读法不同。实证：某会话里 39 次手工启动同一个脆弱 DevTools 资源——
audit 读法 = 单点资源饱和（病理）；harvest 读法 = 高频手工操作（**这里缺一个带重试/健康检查的 harness**）。
**同一条物证，两个场景读出两个不同结论。** 这就是它们该是一个 skill 的三个 mode 而非三个 skill 的原因。

## 6. P3：区分合法演化与病理漂移

```
最终目标 ≠ 初始目标
  ├─ 变更点可追溯到某条 user message → 合法演化，动作是「重新对齐」
  └─ 追溯不到                       → agent 自漂，动作是「纠正」
```

依据：**user message 是唯一来自系统外部的物证**，叙事流吸收不掉它。
没有 P3，审计员会把用户的合法改需求误报成 agent 漂移。

**P3 也面向用户本人，不只面向审计员。** 实证：某 8000+ 行会话有 8 次以上目标切换，全部由用户引入
（合法），但没有一次记录 supersedes 关系，以至于中途用户自己要问
"我需要你完整来看我们原来的目标 和目前的进度"——**用户自己迷失了**。

`two-pass-session-reader` 的 `objective_record.introduced_by` / `supersedes` 字段已预见此点，
是那个 skill 里质量最高的部分，值得原样继承。

## 7. 为什么 RAG / agent-memory 路线必然失败

这条路线被实际尝试过并由用户判定失败（"基本上没有做到任何我们想要的"）。失败是**结构性的**：

> 向量检索只能检索**叙事流**——因为只有叙事流是自然语言、才可嵌入。
> 而价值在**物证流**：某文件被改了 12 次、某命令跑了 39 次、仪器分叉成 4 个副本。
> **这些东西没有语义，嵌入之后什么都不是。**

RAG 把 session 当文本语料，于是它精确地保留了会说谎的那一半，丢弃了不会说谎的那一半。
**它和 compaction 犯的是同一个错误，只是换了个实现。**

这条必须写死在 skill 里，否则下一个 agent 还会提议"要不上个向量库"。

## 8. 上下文边界纪律

```
GB 级物证  →  [脚本进程内消化]  →  KB 级指标  →  [上下文]
```

实测：读 72 MB session 只耗约 4 KB 上下文（**~20000:1**），比 compaction 的 200:1 高效百倍，
且保留的恰是 compaction 丢弃的东西。

→ **问题从来不是"信息太多"，而是"压缩时保留了错误的东西"。**
脚本聚合保留统计量（物证的形状），compaction 保留叙事。同样是压缩，方向相反。

防膨胀的两个机制：**行号指针**（按需回原文取窗口）与**可复现命令**（重新生成物证比存物证便宜几个量级）。

## 9. 唯一不变量

> **任何结论都必须由物证流支撑；叙事流只能作为「待质证的宣称」进入分析。**

这条替换掉 `two-pass-session-reader` 的"必须两遍全读"——后者在 1.5 GB 文件上物理不可执行。
"两遍"降级为手段：禁止的是"只读上一遍的摘要"，不是"没读完全文"。

## 10. 终点是动作，不是报告

```
继续    无显著裂缝，放行
干预    回到第 K 个决策点重来（给出那个点和它的隐藏假设）
升层    问题被误当成执行问题，需回设计层重开
停止    裂缝跨越 agent 能力边界 → 交回给人，附上必须由人回答的那个问题
```

报告是这个动作的附件，不是产物。任何"干预/升层/停止"都必须留下一条晋升记录，否则同一病理下周复发。

## 11. 晋升梯

```
观察 1 次                  → handoff packet
跨会话复发 2 次             → 失效边 / gate      （禁止性："别做 X / X 之后 Y 失效"）
复发 ≥3 次且有稳定操作序列   → skill（+harness）  （生成性："要做 Z 就按此序列"）
```

**gate 与 skill 的分界**：知识形式是"别做 X / X 之后 Y 失效" → gate（禁止性）；
是"要做 Z 就按这个序列" → skill（生成性）；序列需要工具托底 → harness。

**报告会过期，失效表和 skill 库不会。** 用得越久，同类风险从"不可预知"降级为"已标价"的比例越高。
