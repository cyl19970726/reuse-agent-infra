# Handoff Packet 模板

## 第一原则

**物证优先的索引，不是摘要。** 否则你只是人工做了第 N+1 次 compaction，同样丢物证。

两个防膨胀机制，缺一不可：
- **每条结论挂原始 JSONL 行号** —— 接手方可按需回原文取窗口
- **附可复现命令** —— 重新生成物证比存储物证便宜几个量级

## 结构

### 1. 原始目标（逐字，不转述）

用户消息按时序列表，每条标注：行号 / 原话 / 性质（初始 / 扩展 / 纠正 / 收敛 / 约束）。
**必须用 `objective_trace.substantive`（已过滤 ambient 注入与"继续"泵）**，不要用粗筛结果。
末尾给出 P3 判定：目标演化是否 100% 由 user message 引入；若否，指出 agent 自漂的起点。

### 2. 当前真实状态（只从物证重建，不引用 agent 宣称）

- 仪器清单：哪些 tool/script 文件、在哪几个工作树、各自 HEAD
- 证据代际表：每条证据 ← 哪个 commit / 哪把尺子 / 是否 stale
- 已确认的缺陷清单（带文件:行号）

### 3. 心智模型 / 设计定稿

当前有效的模型与结构决策。这一段是唯一允许以叙事为主的部分，因此必须最短。

### 4. 关键实测数据

**所有会死于压缩的数字放这里**：计数、比率、分布、分位、行号。
这一段是整个 packet 最重要的部分——它是物证的浓缩，不是结论的复述。

### 5. 基线 / 对照

跨会话可比的分布，用于判断本次观测是否异常。

### 6. 已证伪 ⚠️ 必需项

**上一个 agent 说错的话。** 原始 8 段模板漏了这一段，实战中发现它比"已排除路线"更关键：
若不写，接手方会把前任的错误结论当既定事实继续用。
这是唯一一段专门用于**阻止叙事流被继承**的。

格式：`我提过的 | 被什么证伪 | 状态（废弃 / 降级为占位符 / 结论反转）`

### 7. 未证伪的假设

一直当真、从未验证的东西。标注"为何未验证"与"决定性证据在哪"。

### 8. 失效表

本项目当前已知的全部失效边 + 当前被违反的边。
比"先冻结 commit"这类单句建议信息量大得多，且可继承。

### 9. 明确非目标

不要做什么。包括审计员的硬约束（禁止解题、禁止 RAG 路线、禁止绝对计数判断）。

### 10. 下一步 —— 按**当前目标**排序，不按审计员优先级

**排序基准是 §0/§1 认定的当前目标，不是初始目标，更不是审计员自己发现的问题清单。**
写完 §10 必须回头对一次：**第 1 项服务的是用户当前目标吗？**
若第 1 项是"修工具 / 修副本 / 修 parser"而用户当前目标是产出某个交付物，
**顺序就错了**——除非能说清那个交付物在物理上依赖它。审计员发现的问题写进"支撑项"，
它们不阻塞主线（见 §实战修订记录 第 6 条）。

最后必须有一条：**什么结果会证伪当前整条路线。**

### 附：可复现命令

生成上述全部数字的确切命令。

## 实战修订记录

第一次实战（本 skill 自身的设计讨论）暴露的模板问题：

1. **原 8 段漏了「已证伪」** → 已升为必需项（§6）。理由见上。
2. **S（状态重建）与 P2（沉淀）边界模糊** —— 基线分布放在"当前状态"里，但它其实是跨会话可复用资产。
   处置：单列为 §5，归属 P2。
3. **「可复现命令」原不在模板内**，但它是保持 packet 在 KB 级的关键机制 → 已升为与行号指针并列的
   第二个防膨胀手段。

第二次实战（`CASE-C`，Example project，44 小时 / 9439 行 / 3 个工作树）暴露的：

4. **§2 缺「owner 可见性」这一格。** 原 §2 只要求列"仪器在哪几个工作树、各自 HEAD"，
   覆盖不了本次最重要的事实：**26 个 commit、411 个文件、+62942 行的工程全在未合并的
   worktree 分支上，而 owner 常驻目录 `main` 里一件都没有**。
   → §2 必须包含一张三列表：`位置 | 领先 main 多少 | 同一条命令在此处的实测结果`。
   本次那张表一眼看穿问题：同一条 `pytest tools/tests -q` 在三处分别是 **77 / 320 / 216 passed**。
   **同命令跨副本的结果差**是最便宜、最不可辩驳的分叉证据——比任何 diff 都短。
5. **§2 应包含「会话死后落盘的产物」**。检测只需 `stat`：产物 mtime > session 文件 mtime。
   本次子 agent 在父会话断线 90 秒后写完整版 20 张证据 + audit（`status=BUILDER_CLOSED`），
   如果只读 session，这一版对接手方**完全不存在**。见 signatures.md §孤儿产物。

第三次实战（`CASE-F`，Codex，714 行 / 目标从"个人支持请求"演化到"做成文章+视频"）暴露的
**最严重的一条**——它由用户当场指出（"发现你都没有真正的把任务续上是为什么"）：

6. **§1 记录目标演化，§10 却不继承它——两节之间没有链接，模板不强制。**
   本次 §1 正确记录了 L276 主线转向内容生产、L400/L526 两次纠偏，P3 也正确判为"合法演化、无自漂"。
   但 §10 的第 1、2 项被排成了**审计员自己发现的工具问题**（三副本分叉、parser bug），
   还各打了"[阻塞级]"，而用户真正在做的事（文章 / 视频脚本 / 呈现形式 / 推特）排在第 3、4 项。
   **产出物成了附录，工具修复成了主线。**
   → 根因在 SKILL.md §3：首尾一刀的决策树写的是「可追溯到 user message → **动作是重新对齐**」，
   而"重新对齐"是一个**动作**，不是一个判定标签。判出"合法演化"就停手 = 只做了诊断。
   → 处置：①§10 改为按当前目标排序（见上）；②新增 §0「任务续接点」，
   **在 packet 最前面用一张演化图给出"初始目标 → 当前目标"，并明说接手方第一件事是什么**；
   ③SKILL.md §3 补一句"重新对齐是动作"。

7. **packet 自身会变成"引用了一个已不再成立的东西"。**
   本次修完副本分叉后，§2/§6/§8 里六处"未同步 / ❌违反"当场变成假话，
   而 packet 是一份静态文件，没有任何失效传播机制——**它得了它自己诊断的病。**
   → 处置：修完任何 §8 失效边后，必须回改 §2/§6/§8 的状态行，
   且**保留病历、标注"修复前状态，勿当现状"**（病历本身是最好的 dogfood 素材，不要删）。

第四次实战（2026-08-18，Owner 复核「很多时候 handoff 都没有真正做好超集」，
审计本 skill 自身，会话 `CASE-AC`）暴露的五条——**handoff 是全 skill 复合度最高的产物，
却是强制力最弱的一环**：

8. **完成度是警告不是闸。** 脚本生成后只 `print("未填完…不可交接")` 然后 exit 0；
   而同一 skill 里 drill 是"拒绝执行"、sync 是"逐关拒绝"。修订记录 #6/#7 加 Example project 共三次
   事故复发，按晋升梯（复发 ≥2 → gate）早该落闸——skill 在自己身上违反了自己的晋升梯。
   → 已修：`--check <packet.md>`，§0/§1-P3/§6/§7/§8/§10 残留 TODO 即 REFUSED（exit 1）；
   §2/§3/§9 只警告但**点名**（沉默的缺口才是病）。
   连带发现：原警告清单只点名 §6/§7/§8/§10，**漏了 §0**——#6 事故后新增的防复发字段
   没有进入防复发机制，修复只做了半截。
9. **P2 实际不在超集里。** 公式 handoff = S+P1+P2+P3，但脚本不产任何序列提取，
   §5 装的是基线（#2 把基线"归属 P2"，基线 ≠ 可复用序列）。真公式曾是 S+P1+P3原料+基线。
   → 已修：§5.5 内嵌 harvest 的操作剖面（同一 scan 结果，零额外成本）+ 完整 harvest 的
   可复现命令。
10. **§6 让病人自己写病历。** "已证伪"要由**正被换掉的 agent** 凭记忆填——它的世界模型
    已与物证脱钩正是交接的原因；这结构上就是本 skill 判为原理上不可能的自察，放在了
    agent 状态最差的时刻。而"被证伪"其实有物证：用户的不满句式 + 其后的更正/回滚。
    → 已修：脚本用 calibrate 的宽召回种子预填"疑似（L行号，特征）→ 待质证"候选行，
    作者的工作从「回忆」变成「质证」。实测（本会话）：5 条候选 4 条真命中、1 条误报
    （"没有问题"击中 still-broken 种子）——误报暴露在表里等质证，好过真命中沉默消失。
11. **生前交接与死后交接没分流。** Example project 案例里父会话断线、孤儿产物 90 秒后落盘——
    执行 agent 已死时 §3/§9 这类"要采访本人"的节无人可填，留 TODO 是假装会有人来填。
    → 已修：`--post-mortem` 把 §3/§9 标"不可得"（显式声明，接手方不再等待），
    §6 加注"由观察者只从物证填写，禁止引用前任叙事流"。

## 触发时机

不要用 compaction 计数当触发器（实测 p50 = 10，任何小阈值都会命中近 100% 会话）。

```
硬触发   compaction ≥3 或 声明-偏离 >2×  → 强制跑一次审计（不是强制 handoff）
真判据   审计输出四选一                   → 继续 / 干预 / 升层 / 停止
```

真正的 handoff 理由不是"上下文满了"，而是**"这个 agent 的世界模型已与物证脱钩"**。

## 看门狗（预防，比 handoff 更早的干预点）

```
任务开始   agent 显式声明预期（N 分钟 / M 次工具调用 / K 个文件）
运行中     实际 > 2× 声明 → 触发只读审计（并行，不打断）
审计内容   首尾一刀（初始目标 vs 最近动作）+ B 类签名扫描，几秒钟
```

声明本身有独立价值：**它逼 agent 把隐含计划显式化，而显式化的计划才可能被证伪。**
且这不是新机制——「声明的预期 vs 实际耗时」就是 A 类裂缝的实时版，与事后审计共用同一张签名表。
