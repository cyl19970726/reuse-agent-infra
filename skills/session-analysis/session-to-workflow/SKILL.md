# 从历史构建工作流

核心结构只有：**阶段 → 步骤 → 资产和流程**。先理解过去，再设计下一次更好的做法。历史的操作顺序、步骤数量和 Agent 数量都可以调整。

先读[心智模型](references/mental-model.md)与[两个 skill 的配合说明](references/forensics-cooperation.md)。前者解释结构与工作台目标，后者规定职责、案例证据交接、结束条件和补查方式。生成报告使用[报告模板](references/workflow-report-template.md)，按任务裁剪，不为填模板增加工作。

## 先确定范围与交付点

沿用用户已给的目标，明确本次要恢复哪类工作、哪些会话和资产，以及本次交付到哪一步。跨会话按共同业务目标归组；区分原需求、后来澄清与需求变更。报告、业务 skill、工作台和验证按当前授权推进；验证只做到约定资产，不因流程图还有后续阶段就自动扩成完整业务生产。

同时恢复**长期目的、当前阶段目标、本轮任务**及相互关系。审计对象包含用户请求、Agent 的理解与追问、双方反馈和审计者自己的建议。按[目标与协作审计](references/intent-and-collaboration-audit.md)检查请求是否足以支持当时的路线选择；不得把“来自用户”当作“信息充分、事实正确、代价合理”。已确认要求由 Agent 维护，关键未知按其影响集中澄清，不要求用户预先设计工作流。

涉及多个账号或独立业务空间时，先明确上下文归属，再恢复各自的目标、库存和决定。参考[工作区与选题入口](references/workspace-and-topic-intake.md)：长期定位与单篇定位分开，跨区复用显式带来源；来源发现、选题选择、内容制作的效果分别评价。

## 四段推进

1. **恢复历史。** 历史读取与质证必须使用 [session-forensics](../session-forensics/SKILL.md)，先读取原 skill 并按适用能力执行。核对当时配置、实际产物及 Reviewer/subagent 反证，填写案例证据表：需求及输入、尝试、资产、反馈、修改、结果。重要判断附原始定位与版本；成功与失败均保留，缺失标未知。禁止自写日志提取器，或用 RAG、记忆、摘要代替原始取证。依赖路径失效时先定位同名 skill，确实缺失则说明受影响范围。
2. **反思重建。** 先形成目标与关键资产的全貌，再带着问题通过原 skill 回查历史。区分初次必要探索、可复用做法和可避免返工；依据当时可知信息分析行为与后果，不凭后来答案责备探索。按独立目标、交付和返工边界取舍阶段与步骤，写清“历史做法 → 调整理由 → 新步骤”。每步明确输入、中间资产、输出、复用依赖，以及生成、审阅、筛选、返工和结束条件。工具、策略与 Agent 放在步骤内部。交付分层可读的候选报告，经过下述双角度审阅后修订。
3. **落地方法。** 在已授权范围内，优先补已有业务 skill 和工作台。产出的业务指导默认放在所属项目 `.agents/skills/`，详细条件按需引用；只有用户明确授权具体 skill 的全局范围时才安装全局副本。案例答案与待验证改进不能伪装成普适规则。工作台按下述持续协作目标建设；方法要求、实际实现与接受状态分别记录。
4. **实际验证。** 先固定同一需求时点、输入、比较节点、预算与检查问题，再生成新产物；保存首次结果、实际模型/工具、指导和修订。旧失败是否改善、旧成功是否退化、投入与审阅负担如何变化，都用实际产物和检查证明。缺少旧初稿或可比投入就缩小比较范围；后来答案只进评审侧，不能悄悄成为新版独有输入。相关步骤通过后，再以未参与提炼的案例检验迁移。未执行、仅局部验证和未覆盖部分明确保留；不把旧产物重新分类或作者自评当重做成功。

每段的交接和返回条件以[配合说明](references/forensics-cooperation.md#什么时候向前走什么时候返回)为准。证据不足时定向补查或收窄结论，不无边界地翻完整历史库。

## 两个角度同时审阅

首次重建或重大结构调整，用两个独立 subagent 并行审同一候选：一位核历史与用户意图，一位核方法设计与持续协作。主 Agent 提供相同目标、版本及所需关联资产，汇合分歧、修改并让相关侧复验；不按票数决定，不叠加全部建议。普通局部修改只复验相关意见。职责、输入和范围见[配合说明](references/forensics-cooperation.md#两个审阅角度与最终责任)；双审本身的价值也须按不同发现与投入评价。

## 工作台从持续协作出发

工作台维持用户与 Agent 的共享上下文：整体目标、所有关键阶段和步骤、关键资产及依赖、重要意见和决定、修改与接受记录都清楚可达。当前重点帮助用户回到工作，前面成果和决定跨轮次保留，详细历史按需展开。

概览同时说明最终为了什么、当前阶段怎样服务它、本轮为何做这份资产；关键受众与价值承诺保留确认来源。定位依赖研究结果时，开始只对齐目的与必要边界，报告形成后再集中提交主题、受众、价值、载体和商业方案。分别标明历史决定、当前有效要求和新建议，避免分散追问或把精确定价设成研究的前置条件。

先让未持续跟进的用户能说明全貌、成果、变化及原因、下一步，并追溯自己的意见如何被处理，再验证反馈和按需授权操作。用户本人、授权代理、技术和读者的接受范围分别记录。工作台可用、作品合格与方法有效分别验证；具体呈现与跨轮次验收见[心智模型](references/mental-model.md#4-工作台为什么要建)。

## 交付

工作流报告放在已有任务目录；跨选题方法恢复可放 `research/workflows/<工作流名>/`。案例证据可放报告内，较大时单独引用。原始会话、媒体与已有资产留原处，保留明确的当前入口及历史版本，不另抄执行日志。

同一次重建维护一份主报告：目标、定位、历史诊断、阶段与步骤、工作台和验证建议放在对应章节，后续反馈就地修订。关键资产可以是章节，不等于必须另建文件；原始证据、媒体和审阅明细按需链接。工作台默认指向这份主报告，不让用户跨多份建议自行拼出全貌。

交付时给出当前报告、实现和验证结果及限制。确认取舍有依据、每步可执行、资产与意见可追溯、本次验证停在约定范围。常规修复沿用已有授权；不因总结历史自动发布内容、删除旧资产或启动定时任务。
